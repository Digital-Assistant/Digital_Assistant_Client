# Suggested improvements

## A. Audit recipe, framework and tools

1. **EXEC-03 false negative on untagged code fences.** `_common.extract_fenced_commands` (deterministic-audit/audit/rules/checks/_common.py:143-166) only reads fences tagged bash/sh/shell/console. This repo's README.md lines 9-18 has an untagged fence starting `npm install`, and AGENTS.md line 11 documents `npm ci` inline. Result: BLOCKER F-004 for a documented install path. Fix: treat untagged fences whose lines start with a known head tool as shell, or also scan inline code that begins with a recognised install command. The same limitation makes EXEC-06 ("no fenced shell commands documented") a vacuous PASS here.
2. **NAV-02 ignores bundler and extension entry points.** `_node_entry` (checks/nav.py:154-172) reads only package.json `main`/`bin`/`exports` plus a fixed list of root file names. A webpack project with `entry` in `webpack.config.js` (7 entries incl. `./src/main.tsx`) and a Manifest V3 `background.service_worker` fails. `src/main.tsx` and `src/index.*` are not in the list. Suggest: include `src/main.{ts,tsx,js}`, `src/index.*`, webpack/vite config `entry`, and `manifest.json` background/content scripts.
3. **Disputing an engine false positive needs set-disposition, which blocks a "stages 0-3 only" run.** `add-check` PASS over a pending finding exits 2 ("rule 7 ... EXEC-03 is PASS, so its finding must be rejected"). When a person is not yet in the loop (Stage 3), a correct dispute cannot be recorded. Suggest a way to attach a "proposed override" to a check without changing the verdict (or allow `add-check` to stage a dispute that is applied when the finding is rejected). I worked around it by saving fragments under `pending-disputes/`, which no tool reads.
4. **AGT-08 flags a one-line `@AGENTS.md` import as both a "shadowed pair" (F-012) and a "vendor-only competitor" (F-013).** The check's own pitfall says a deliberate pointer is accepted, and Claude Code expands the import so both are loaded. The engine verdict was FAIL; the rubric supports only PARTIAL here. Suggest the classifier recognise a file whose entire content is `@<path>` as a pointer and drop both findings. Evidence: CLAUDE.md is 11 bytes.
5. **SEC-01 raises a BLOCKER finding for a PARTIAL.** No `.env` is tracked; the repo ignores `environments/*`. Only a missing `.env`/`.env.*` ignore rule exists, yet the finding inherits BLOCKER (F-006) and counts as a blocker remaining in the summary ("1 PARTIAL"). The rubric calls only a tracked `.env` "the blocker". Suggest capping the finding at DEGRADER when nothing is tracked.
6. **EXEC-04 flags optional knobs that are documented elsewhere** (`UDAN_ENV_FILE` in scripts/ci/README.md; `EXPECTED_VERSION` in a script header). The check could accept a key documented in any committed doc, or recognise `${VAR:-}` default-empty usage as optional. Also the example file lives at `environments/env.example`, not the root; the engine matched by name only, which worked, but the profile text says it reads root-named files only. Clarify.
7. **CI-02 UNKNOWN vs FAIL ambiguity.** When no local verb resolves but CI calls `tsc` and `npm audit` directly, the engine returns UNKNOWN and the rubric's FAIL branch is arguably also true. Say which wins when both apply. The engine also does not follow `scripts/ci/*.sh` that ci.yml calls (CI-03 PASS is therefore trivial).
8. **TST-01 evidence cites an irrelevant file** (`.gitattributes`, F-007 evidence) for a "no test files" FAIL. The absence proof should be a `searches[]` glob entry; the finding carries `searches: []`. Several engine findings (F-001, F-007) have thin or placeholder evidence (no line numbers). For F-006/F-021 the evidence is the same four `.gitignore` entries repeated.
9. **EXEC-05 and the GENERATED classifier miss design-tool exports.** `src/imports/` holds ~42 Figma-export files (names like `HomePageUser-14-1082.tsx`, `svg-0ikchrah8d.ts`, ~627 KB, no header) and `facts.py` shows `generated: 0`. Consider a name pattern or a Figma marker, or at least an agent note in the check's Pitfalls.
10. **IDX-01 credits the wrong harness.** The PASS cites `~/.config/opencode/opencode.jsonc`, while the harness in intake is Claude Code. The recipe says to ask which config the harness reads; the engine does not take the intake's harness into account. Evidence-wise the PASS is right (the MCP is live) but for the wrong reason.
11. **IDX-03 cannot be settled without Tier C, and `detect_changes` failed** ("base_branch or HEAD is not a commit", with the repo on branch `dev`). Document a recommended fallback (compare `index_status.indexed_at` with `git log -1 --format=%cI`) so every run reaches the same verdict.
12. **`--exclude` is spelled twice** (`node_modules` and `node_modules/*`) to be safe, because the intake's `excluded` list is not passed to facts.py/engine.py automatically. The recipe says to forward; a `--intake` flag on both tools would remove a manual step and a drift risk.
13. **Stage 3 ergonomics:** `report.py status` shows only 8 pending findings and says `pending_omitted: 32`; there is no flag for the full list, so I read the JSON directly. A `--all` option would avoid that.
14. **Checks that fit a browser extension poorly:** NAV-02 (above), TST-* (the only real verification is a Chromium smoke run against a deployed TEST backend, not a unit suite), EXEC-01 (Node pin is in CI env, not a manifest), AGT-03/DOC-01/DOC-02 (docs live in README plus `scripts/ci/README.md`, the rubric requires a `docs/` tree), HYG-08 (the release process is documented in README "CI and releases" and AGENTS.md, but the check wants a file whose name contains "release"). Consider letting a README section named "release"/"releasing" count, as the owner clearly documents it.
15. Minor: `Stage 1` asks to record `run_context.stack_profile` but no subcommand writes it (already known in the recipe). The first command line in my session wrote a stray `cat > $TMPDIR/x` failure (my own mistake, no file created).

## B. The audited project (Digital_Assistant_Client), beyond the findings

1. **Add the seven verbs as package.json scripts** wrapping what already exists: `typecheck` = `tsc --noEmit`, `security` = `npm audit --omit=dev --audit-level=high`, `check` = typecheck + (future) test, `format`/`format:check`/`lint` after choosing Prettier and ESLint. This single change clears or reduces CMD-01, CMD-02, AGT-05, TOOL-01/02/04, CI-02 and the TST/BASE chain, and lets CI call the same names (`npm run typecheck`) so local and CI cannot drift.
2. **Pin Node in the repo**: add `"engines": {"node": ">=22"}` and an `.nvmrc` (22) so `ci.yml` `NODE_VERSION` can read it (`node-version-file`).
3. **Turn on `strict` in tsconfig incrementally** (currently `strict: false`, `noImplicitAny: false`), file by file, and add a first test. The 14-check behaviour list in README is already a good test plan; `scripts/ci/smoke-extension.mjs` already automates 4 of them but runs only after Deploy to TEST, not on PRs. Running the local-only checks (1, 2, 6) in a PR job against the built zip would give a real test gate with no backend.
4. **`npm audit` is report-only with 11 known high findings** (ci.yml:126-143). Decide: fix or accept, then make it gating or record the exception in AGENTS.md. Until then "CI Gate" green does not mean dependencies are clean.
5. **Repo is not self-contained for agents:** AGENTS.md line 3 defers to "the workspace AGENTS.md" outside this repo (Docker rules, branch rules). A standalone clone loses it. Copy the few rules an agent here needs.
6. **Stale or dead files an agent will trip on:** `src/guidelines/Guidelines.md` describes "UDAN-UI" and a Redux store in the SDK, i.e. the sibling repo's docs; `src/test-vite-shadow-css.html`, `src/App.debug.tsx`, `src/App.simple-shadow.tsx` and four `App*.tsx` variants (which one is live is not stated; `main.tsx` is the entry); `src/imports/` is Figma export output (~627 KB) and not marked as generated. Add a one-line "do not hand-edit src/imports/" rule to AGENTS.md and a header or README in that folder.
7. **Add `.env`/`.env.*` and secret-shape lines to `.gitignore`** (SEC-01/SEC-03): the repo is public and AGENTS.md puts weight on never shipping a secret; `environments/*` protects only that folder.
8. **Docs home:** create `docs/` (even one page of architecture: worker, content scripts, SDK boundary, runtime TEST/PROD switch) and name it in AGENTS.md; the knowledge now sits in a 38-line AGENTS.md with long dense bullets plus README. Add an ADR for the webpack 5.105.4 pin and the Babel 8 stall, now only in `dependabot.yml` comments.
9. **Cheap hygiene wins** (all COSMETIC): CODEOWNERS, PR template, SECURITY.md (public repo needs a disclosure channel), CONTRIBUTING (AGENTS.md content would do). `CHANGELOG.md` will appear with the first Release Please release; until then HYG-07 stays FAIL.
10. **Branch protection as code:** the AGENTS.md describes a "Protect dev" ruleset (required `CI Gate`, strict policy). Export it (`gh api repos/.../rulesets`) into the repo or a Terraform file so CI-04 can be confirmed from the tree.
11. **Edge detail an auditor noticed:** package.json `name` is `UDAN-Frontend` while release-please uses `digital-assistant-client`; the extension has `manifest-firefox.json` that is copied but unused; `drop_console` applies to qa and prod builds only. Not findings, just things an agent will ask about.

## Notes from landing and Stage 4 (parent session)
- Probes (format:check, lint, typecheck, test) could not run on any repo: `engine.py` runs verbs only against the audited path, and `report.py import-engine` refuses a report whose target differs from the draft's, so a disposable clone cannot be probed. The owner's "disposable worktree" intent is not achievable with the current tools.
- Stage 4 cannot be done before Stage 3 ends if an engine false positive must be disputed: `add-check` to PASS needs the finding rejected first, which needs the owner. A recipe step for "queue disputes" would help background sessions.
- CI gating of this docs landing: all four repos' CI already has a job-level docs-only skip so the required `CI Gate` still reports; `[skip ci]` in a commit would leave the required check pending and block the PR, so it was not used. Gaps: SDK's skip list allows only `*.md`, `artefacts/**`, `LICENSE`, `CHANGELOG.md` (the `.json` report triggers the full gate); Server's `ci.yml` has no docs-only skip. Consider adding `docs/agentic-readiness-report/**` to those filters.
- Owner decisions that differ across repos for the same pattern (CLAUDE.md pointer: rejected in Client and microServices, confirmed in Server) were taken per repo at Stage 4; the engine could not distinguish an `@AGENTS.md` import stub from a shadowing file.
- microServices: owner rejected F-046/F-047 (tracked `environments/local.env` files are intentional for local developer setup). The audit did not verify whether any value in them is live.
